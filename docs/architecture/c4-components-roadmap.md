# C4 Components Roadmap — Pig Console

Дорожная карта описания **слоя Components (уровень 3)** проекта
**Pi Games (Pig) Console**. Является продолжением `c4-roadmap.md`.

## Статус

Выполнено:

- **Context** (`context.c4`) — границы системы и внешние зависимости.
- **Containers** (`containers.c4`) — 3 контейнера: **Pig Shell**, **Pig Library**, **Pig Pkg**.

После пересмотра состава Containers-слоя внутренние нюансы реализации (например, прежние Game Library и Package/Update Manager) инкапсулированы внутри контейнера **Pig Library**, а прежний Game Launcher переименован в **Pig Pkg** с сужением зоны ответственности. Поэтому Components-слой теперь детализирует **два** контейнера: Pig Shell и Pig Library. Pig Pkg — узкоспециализированная SUID-утилита, декомпозиция которой, скорее всего, не потребуется.

## Текущее видение декомпозиции

### Pig Shell

Предполагаемые компоненты внутри контейнера `pig-shell` (гипотеза для старта):

- **Compositor Core** — обёртка над внешней библиотекой Wayland-композитора (например, smithay): поверхности, рендеринг, seat-ввод, приём ivi-поверхностей от клиентов. На Components-уровне сюда направляются связи «создаёт ivi-поверхность» от игр, браузера и терминала.
- **Shell / Layout Manager** — логика раскладки окон (игра, браузер, терминал), фокус и зонирование поверхностей; взаимодействует с Compositor Core.
- **Gamepad Input** — обработка ввода с геймпада и маппинг в действия навигации по интерфейсу.
- **App Launcher** — запуск браузера и терминала как внешних приложений.
- **UI / Data-Binding** — экраны каталога и библиотеки игр; отображение данных, полученных от Pig Library, и обработка команд пользователя для делегирования в Pig Library.

### Pig Library

Предполагаемые компоненты внутри контейнера `pig-library` (гипотеза для старта):

- **Game Library Store** — владелец установленных игр и их ресурсов (сохранения, скриншоты); хранение настроек, ассоциированных с игрой. Внутренний нюанс реализации — персистентное хранилище (лёгкая СУБД, не обязательно SQLite); используется исключительно внутри Pig Library.
- **Package Manager** — клиент внешнего репозитория игр: поиск, получение метаданных, скачивание; устанавливает и удаляет игры в/из хранилища.
- **Update Detector** — сравнение версий установленных игр и репозитория (через Package Manager), опрос PackageKit на наличие системных обновлений; источник уведомлений для Pig Shell.
- **Game Launcher (внутренний)** — оркестрация запуска игры: подготовка пути к пакету, вызов **Pig Pkg** для монтирования и изоляции, контроль результата.
- **D-Bus Facade** — единственная точка взаимодействия с **Pig Shell**: предоставляет данные (списки игр, наличие обновлений) и принимает команды (запуск, установка, удаление, обновление). Остальные компоненты Pig Library доступны только через фасад.

### Pig Pkg

Лёгкая SUID-утилита; Components-декомпозиция, скорее всего, не потребуется. При появлении потребности рассмотреть выделение:

- **squashfs Mounter** — монтирование/размонтирование образа.
- **Manifest Reader** — чтение и парсинг манифеста пакета.
- **Sandbox Composer** — построение изоляции (namespaces, seccomp и т.п.) на основании манифеста и пользовательских разрешений; понижение привилегий; exec приложения.

## Влияние на связи модели

При переносе на Components-уровень связи контейнеров перераспределятся между их компонентами:

| Связь на Containers | Предполагаемый адресат на Components |
| --- | --- |
| `games/browser/terminal -> pig-shell "создаёт ivi-поверхность"` | `pig-shell.compositor-core` |
| `pig-shell -> browser/terminal "запускает и управляет окном"` | `pig-shell.app-launcher` / `pig-shell.layout-manager` |
| `pig-shell <-> pig-library "запрашивает данные и делегирует действия"` | `pig-shell.ui-data-binding` ↔ `pig-library.dbus-facade` |
| `pig-library -> game-repository "ищет и скачивает игры"` | `pig-library.package-manager` |
| `pig-library -> packagekit "системные обновления"` | `pig-library.update-detector` / `pig-library.package-manager` |
| `pig-library -> pig-pkg "запускает игру из пакета"` | `pig-library.game-launcher` → `pig-pkg` |

Связи внутри `pig-shell` (layout-менеджер ↔ compositor-core, gamepad-input → shell и т.п.) и внутри `pig-library` (facade ↔ store, package-manager ↔ store, update-detector → package-manager и т.п.) будут заданы явно на этом слое.

## Шаги при переходе к слою Components

1. Добавить вид `component` в `spec.c4` (shape component).
2. Создать `components.c4` с `extend pig-console-shell.pig-shell { ... }` и `extend pig-console-shell.pig-library { ... }` — компоненты и внутренние связи.
3. Обновить/уточнить связи внешних элементов с учётом таблицы выше.
4. Создать компонентные views (`view shell-components of pig-console-shell.pig-shell`, `view library-components of pig-console-shell.pig-library`), провалидировать проект.
5. Декомпозировать **Pig Pkg** только при появлении практической потребности.
