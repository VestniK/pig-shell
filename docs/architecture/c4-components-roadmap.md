# C4 Components Roadmap — Pig Console

Дорожная карта описания **слоя Components (уровень 3)** проекта
**Pi Games (Pig) Console**. Является продолжением `c4-roadmap.md`.

## Статус

Выполнено:

- **Context** (`context.c4`) — границы системы и внешние зависимости.
- **Containers** (`containers.c4`) — 4 контейнера: UI Shell, Game Launcher, Package/Update Manager, Game Library.

По решению на Containers-слое **Compositor Core свёрнут в контейнер UI Shell**: оболочка и композитор живут в одном процессе, поэтому по канону C4 это один контейнер. Его внутренняя структура должна быть детализирована именно на слое Components.

## Текущее видение декомпозиции UI Shell

Предполагаемые компоненты внутри контейнера `ui-shell` (гипотеза для старта):

- **Compositor Core** — обёртка над внешней библиотекой Wayland-композитора (например, smithay): поверхности, рендеринг, seat-ввод, приём ivi-поверхностей от клиентов. На слое Components сюда направляются связи «создаёт ivi-поверхность» от игр, браузера и терминала.
- **Shell / Layout Manager** — логика раскладки окон (игра, браузер, терминал), фокус и зонирование поверхностей; взаимодействует с Compositor Core.
- **Gamepad Input** — обработка ввода с геймпада и маппинг в действия навигации по интерфейсу.
- **App Launcher** — запуск браузера и терминала как внешних приложений.
- **Catalog / Library UI** — экраны каталога и библиотеки игр: поиск, список установленных, страница игры (запуск, настройки, удаление).

Эта гипотеза уточняется при переходе к слою Components; состав может измениться по мере принятия решений по коду.

## Влияние на связи модели

При переносе на Components-уровень связи контейнера `ui-shell` перераспределятся между его компонентами:

| Связь на Containers | Предполагаемый адресат на Components |
| --- | --- |
| `games/browser/terminal -> ui-shell "создаёт ivi-поверхность"` | `ui-shell.compositor-core` |
| `ui-shell -> browser/terminal "запускает и управляет окном"` | `ui-shell.app-launcher` / `ui-shell.layout-manager` |
| `ui-shell -> game-library`, `ui-shell -> game-launcher` | `ui-shell.catalog-library-ui` |
| `package-manager <-> ui-shell` (уведомления/запуск обновлений) | `ui-shell.catalog-library-ui` (или выделенный компонент уведомлений) |

Связи внутри `ui-shell` (layout-менеджер ↔ compositor-core, gamepad-input → shell и т.п.) будут заданы явно на этом слое.

## Шаги при переходе к слою Components

1. Добавить вид `component` в `spec.c4` (shape component).
2. Создать `components.c4` с `extend pig-console-shell.ui-shell { ... }` — компоненты и внутренние связи.
3. Обновить/уточнить связи внешних элементов с учётом таблицы выше.
4. Создать компонентный view (`view components of pig-console-shell.ui-shell`), провалидировать проект.
5. При необходимости декомпозировать и другие контейнеры (например, Game Launcher), если это потребуется для принятия решений по коду.
